# Buch-Migration (`.swbook`)

Verlustfreier Round-Trip eines ganzen Buchs zwischen App-Instanzen (Dev → Prod, zwischen self-hosted Deployments). **Pflicht-Scope:** Pages + Kapitelstruktur + authored `book_settings`. **Optional zuschaltbar** (Export-Checkboxen): Komplettanalyse-Entities, gespeicherte Lektorats-Checks, Chat-Verläufe (alle Session-Arten), Recherche-Board. Nicht enthalten: Drafts/Figuren-Werkstatt, regenerierbare Caches (Extract/Review/LanguageTool/Lektorat-Cache), Integrationen (Blog/HubSpot), Sharing, ACL, Presence. Owner nach Import = importierender User; `user_email` aller übernommenen Zeilen wird auf den Importer gesetzt.

Die menschen-lesbaren Export-Formate (PDF/HTML/MD/EPUB/TXT) sind Einweg-Artefakte; `.swbook` ist das App-eigene Austauschformat für 1:1-Wiederherstellung.

## Bundle-Format (`version: 2`)

ZIP mit Endung `.swbook`:

```
<slug>.swbook            ZIP
├── manifest.json        { format:'schreibwerkstatt-book', version:2, exportedAt, sourceBookId, appVersion,
│                          includes:{ analysis, lektorat, chats, research, werk } }
├── book.json            { book:{ name, description, settings:{…} }, tree:[ node… ] }
├── analysis.json        (nur wenn includes.analysis) Komplettanalyse-Entities
├── lektorat.json        (nur wenn includes.lektorat) { pageChecks:[…] }
└── chats.json           (nur wenn includes.chats)    { sessions:[…], messages:[…] }
└── research.json        (nur wenn includes.research) { items:[…], urls, tags, links, transcripts, segments, speakers }
└── werk.json            (nur wenn includes.werk)     { tables:{ <tabelle>:[…] }, sources:[…] }
```

- `node` = `{ type:'chapter', name, srcId, children:[node…] }` | `{ type:'page', name, html, srcId }`.
- **`srcId`** = Quell-`page_id`/`chapter_id`. Der Import baut daraus `pageIdMap`/`chapterIdMap` (srcId → neue ID); die Extra-Dateien referenzieren Pages/Kapitel ausschliesslich über diese Quell-IDs und werden beim Restore umgeschrieben.
- **Reihenfolge** = Array-Order, gebaut aus dem `book_order`-Tree — inklusive Interleaving (Seite zwischen zwei Kapiteln); der Import setzt sie per `putOrder` exakt so. **Hierarchie** = Nesting (max Tiefe 3, wie chapters). Kapitel-Knoten tragen `excluded` (Export-Ausschluss). Kapitel-Querverweise (`data-xref-id`) schreibt der Import auf die neuen chapter_ids um. Schreibpfad geteilt mit dem Fassungs-Restore: [lib/bundle-apply.js](../lib/bundle-apply.js).
- `settings` = authored Konfig, Key-Liste `SETTINGS_KEYS` in [lib/book-bundle.js](../lib/book-bundle.js) (Sprache/Region, Buchtyp/-kontext, Perspektive/Erzählzeit, Ziele, Stilprofil, Schauplatz/Realitäts-Schalter, Zitier-/Verzeichnis-, Querverweis-, Textsorten- und Recherche-Einstellungen, Schulsystem). Das Schulsystem liegt als eigene Spalte (`book_settings.schulsystem_json`) und wird im Export-Handler zu `settings.schulsystem` ergänzt; beim Import gilt nur ein Objekt mit `vorlage`-Key, normalisiert wird beim Lesen. Übernommen via `applyBundleSettings`: nur Keys, die die Datei trägt — ältere `.swbook`-Dateien ohne spätere Felder lassen die Defaults stehen. `allow_lektor_book_chat` wird beim Import auf 0 gesetzt (ACL-relevant, instanzspezifisch).
- **`version: 2`** trägt immer `srcId` + `manifest.includes` (auch ohne Extras). Alt-Bundles (`version: 1`) bleiben importierbar (kein srcId → leere Maps, keine Extras). Eine ältere Instanz lehnt ein v2-Bundle bewusst ab (`unsupportedVersion`), statt Analyse/Chats stillschweigend zu verlieren.

### Extra-Bloecke (analysis/lektorat/chats/research/werk)

**Der Export nimmt standardmässig alles mit** — alle fünf Blöcke sind in der Export-Karte vorausgewählt; ein Umzug soll nichts verlieren, Abwählen ist die Ausnahme. Mit Extra-Blöcken ist der Export Owner-Recht.

Tabellen-Inventar pro Block — alle book-scoped, IDs werden beim Restore remapped:

- **analysis** (Komplettanalyse): `figures` (+`figure_tags`/`figure_school_paths`/`figure_jobs`/`figure_hobbies`/`figure_relations`/`figure_appearances`/`figure_events`/`page_figure_mentions`), `locations` (+`location_figures`/`location_chapters`), `figure_scenes` (+`scene_figures`/`scene_locations`), `songs` (+`song_figures`/`song_chapters`), `world_facts` (+`world_fact_chapters`), `storylines`, `zeitstrahl_events` (+`zeitstrahl_event_chapters`/`_pages`/`_figures`), `continuity_checks`/`continuity_issues` (+`_figures`/`_chapters`), `ideen`.
- **lektorat**: `page_checks` (gespeicherte Befunde/Stilanalyse/Fazit pro Seite).
- **chats**: `chat_sessions` + `chat_messages` (Abschnitts- und Buch-Chat).

**Der Analyse-Block traegt genau EINE Analyse.** `figures`/`locations`/`figure_scenes`/`songs`/`world_facts`/`zeitstrahl_events`/`continuity_*`/`ideen` sind pro `user_email` skopiert: jeder Mitarbeitende hat seine eigene Komplettanalyse desselben Buchs, mit eigenem `fig_1`-Raum. Beim Restore bekommt jede Zeile die E-Mail des Importierenden (der Quell-User existiert auf der Zielinstanz nicht) — zwei mitgenommene Analysen verschmelzen dabei zu EINEM Katalog, in dem jede Figur zweimal steht. Durchgesetzt auf beiden Seiten: `_pickScope` beim Sammeln (die Analyse des exportierenden Users, sonst die vollstaendigste) und `_restoreToOneScope` beim Einspielen (fuer aeltere Bundles, die noch mehrere tragen; die uebersprungenen Zeilen stehen als `skippedScopes`/`skippedRows` im Job-Resultat und in der Import-Meldung). **Lektorat und Chats bleiben ungefiltert** — Protokolle koennen nebeneinander bestehen; sie tragen nach dem Import allerdings den Importierenden als Autor.

Remap-Regeln im Restore (Reihenfolge respektiert FK-Abhängigkeiten): storylines → figures → figure-Bridges → locations → scenes → songs → world_facts → zeitstrahl_events → continuity → ideen. Natural Keys (`fig_id`/`loc_id`/`song_uid`) werden bei Kollision per `__N`-Suffix eindeutig gemacht — das ist die **letzte Absicherung** fuer beschaedigte oder handgebaute Bundles, kein Weg, zwei Analysen zu vereinen (siehe Kasten oben); im Normalfall greift sie nie. Bridge-Zeilen, deren remappte Referenz fehlt, werden übersprungen (`INSERT OR IGNORE` bzw. `continue`); nullbare FK-Spalten werden auf `NULL` gesetzt. `ideen` (XOR page/chapter): fehlt die remappte Referenz, wird die Zeile verworfen (sonst CHECK-Verletzung). Chat-Sessions mit `kind='page'` brauchen eine remappte `page_id` — fehlt sie, entfällt Session + zugehörige Messages; buchweite Arten (`book`/`research`/`plot`) behalten ihre `kind`.

**Recherche-Block** ([db/book-migration-data/research.js](../db/book-migration-data/research.js)): das Board ist buchweit geteilt, also **kein** Analyse-Scope — alle Fundstücke reisen mit, `user_email` wird wie überall der Importer. BLOBs (Bild, PDF, Interview-Audio) stehen base64 in `research.json`; ihre MIME-Typen laufen beim Einspielen durch die Allowlist in [lib/media-mime.js](../lib/media-mime.js) (dieselbe, die die Auslieferungs-Routen erzwingen) — ein Bundle ist fremde Eingabe, ein `text/html` als Bild-Typ liefe sonst same-origin. Eingespielt **nach** dem Analyse-Block, weil Verknüpfungen auf Figuren/Orte/Szenen dessen id-Maps brauchen: ohne Analyse fallen sie weg, Plot-Beats/-Stränge fallen weg (der Werk-Block, der sie trägt, wird erst danach eingespielt) — gezählt als `linksDropped` im Job-Resultat. Ein beim Export noch laufendes Transkript kommt als `error` an (der Job existiert auf der Zielinstanz nicht); `interview_speakers.source_id` entfällt. Suchindex: `upsertResearch` je Fundstück **nach** der Transaktion.

**Werk-Block** ([db/book-migration-data/werk.js](../db/book-migration-data/werk.js)): alles Übrige, das am Buch hängt — Publikation (`book_publication` samt Cover/Autorfoto), PDF-/DOCX-Profile, Figuren-Aliasse, Figuren-Werkstatt, Plot-Board, Motive/Themen, Bearbeitungsstand, Textsorte/Schlagzeilen je Abschnitt, Quellen am Buch, Share-Links samt Leser-Kommentaren und -Fazits, Entscheide und Einstellungen des Autors (Redundanz-/Namensprüfungs-Ausnahmen, Faktencheck-Urteile, verworfene Welt-Fakten samt Ersatz, Wörterbuch, abgeschaltete LanguageTool-Regeln), alle KI-Ergebnisse (Bewertungen, Erzählprofil, Exposé, Alters-Index, Läufe der Werkstätten, Rückblicke, Fundstellen, Finetune-Exporte), Chat-Bilder sowie Schreibzeit, -sitzungen und Statistik-Verlauf. **Generisch:** `WERK_TABLES` nennt die Tabellen in Abhängigkeitsfolge; Spalten und Fremdschlüssel liest der Kopierer zur Laufzeit aus dem Schema und schlüsselt je Ziel um (Buch, Abschnitt, Kapitel, Importer, Maps des Analyse-Blocks — Figuren, Orte, Szenen, Welt-Fakten —, des Chat- und Recherche-Blocks, Quellen, eigene Maps des Blocks). Fehlt eine Ziel-ID, wird eine nullbare Spalte `NULL`, eine Pflichtspalte verwirft die Zeile (gezählt als `dropped`). BLOBs reisen base64. Zeilen mit `user_email` nur im Scope des Analyse-Blocks — zwei Plot-Boards verschmölzen sonst. Ein PK, der selbst Fremdschlüssel ist (1:1-Tabellen), wird umgeschlüsselt und ersetzt einen am Ziel schon angelegten Default.
- **Share-Links** bekommen **neue Tokens** (die alten URLs bleiben auf der Quellinstanz), `view_count` beginnt bei 0; Kommentare samt Antworten hängen am neuen Link.
- **Chat-Bilder** brauchen den Chat-Block; `context_info.images[].image_id` der Nachrichten wird auf die neuen IDs umgeschrieben.
- **Quellen** sind Bibliothek des Users, nicht des Buchs: es reisen die, die das Buch nutzt (am Buch verknüpft oder im Text zitiert). Der Import gleicht sie **vor** dem Anlegen der Abschnitte mit der Bibliothek des Importierenden ab (DOI, ISBN, Zitierschlüssel, Titel + Jahr — Treffer wird wiederverwendet, sonst neu angelegt, Zitierschlüssel bei Kollision mit Suffix) und schreibt `data-src` der Quellenangaben im Text auf die neuen IDs um ([lib/bundle-apply.js](../lib/bundle-apply.js)#`remapCitations`, analog zu den Kapitel-Querverweisen). Scheitert der Import danach, bleiben angelegte Quellen in der Bibliothek — ein zweiter Import findet sie wieder.
- **Nicht im Werk-Block:** Caches (am Ziel neu berechnet), Nutzungs-/Kostenprotokolle, Zugriff/Freigaben/Verbindungen/Sperren, Fassungen und Abschnitts-Revisionen, reine Ansichtsvorlieben — die Liste mit Kategorie steht im Gate-Test.

**Abgrenzung zur Fassung:** eine Fassung ist Text, Bucheinstellungen und Publikation ([fassungen.md](fassungen.md)); Analyse und Lektorat friert sie nur als Nachweis ein und stellt sie nie wieder her. Der Werk-Block gehört nicht dazu.

## Neue Buchdaten

**Jede neue Tabelle mit Fremdschlüssel-Kette zu `books` reist im `.swbook` mit — oder steht begründet auf der Ausnahmeliste.** Standard ist mitreisen: Autor-Daten und bezahlte KI-Ergebnisse gehen sonst bei Umzug, Sicherung und Instanzwechsel still verloren. Gegated durch [tests/unit/book-data-portability.test.js](../tests/unit/book-data-portability.test.js): er leitet die Buch-Tabellen aus dem End-Schema ab (FK-Kette bis `books`) und verlangt für jede einen Eintrag im Bundle-Code oder in `NICHT_IM_BUNDLE`.

Beim Anlegen einer Buch-Tabelle (im selben Commit wie die Migration):
1. **Standardweg: eine Zeile in `WERK_TABLES`** ([werk.js](../db/book-migration-data/werk.js)) an der Stelle der Abhängigkeitsfolge (Eltern vor Kindern). Der Kopierer übernimmt Spalten und Umschlüsseln aus dem Schema. Zeigt ein Fremdschlüssel auf ein Ziel, das er noch nicht kennt (eine Tabelle ausserhalb aller Blöcke), bekommt `resolve` einen Fall — sonst wird die Spalte `NULL` bzw. die Zeile verworfen. Hängt die Tabelle nicht direkt (`book_id`) oder über einen Elternteil der Liste am Buch, braucht `_selectSql` einen Fall.
2. **Handgeschriebener Block nur mit Grund:** gehört die Tabelle zum Katalog der Komplettanalyse (Figuren, Orte, Szenen, Ereignisse, Ideen) mit dessen Scope- und Merge-Regeln, dann `collectAnalysis`/`restoreAnalysis` (Figuren-Zusätze: [figure-extras.js](../db/book-migration-data/figure-extras.js)).
3. **Rundlauf-Fall** in [tests/integration/book-import.test.js](../tests/integration/book-import.test.js): Zeile anlegen → exportieren → importieren → an der neuen ID wiederfinden; für eine neue Umschlüssel-Art Pflicht.
4. **Fassungen:** nur Text, Bucheinstellungen und Publikation — eine neue Tabelle gehört nur dann hinein, wenn sie eins davon ist; dann in [routes/snapshots/payload.js](../routes/snapshots/payload.js) einfrieren **und** im Restore zurückschreiben. Analyse und Lektorat friert die Fassung über `collectExtras` mit ein (der Gate-Test prüft die Kopplung).
5. **Reihe:** hängt die Tabelle an einer Figur, einem Ort oder einem Welt-Fakt und beschreibt den Gegenstand selbst (nicht seine Stelle im Buch), gehört sie auch in «Aus Vorband übernehmen» ([db/series-carryover.js](../db/series-carryover.js)) — ohne Belege und Abschnitts-Bezüge des Vorbands.

**Ausnahmen** (`NICHT_IM_BUNDLE`, je mit Kategorie): `cache` (aus Text/Lauf abgeleitet, am Ziel neu berechnet), `protokoll` (Nutzung, Kosten, Zeit dieser Instanz), `instanz` (Zugriff, Freigaben, Verbindungen, Sperren, Präsenz), `verlauf` (Fassungen, Revisionen), `praeferenz` (Ansichtsvorliebe), `inhalt` (über die Content-Store-Facade). Eine Kategorie «fehlt noch» gibt es nicht mehr (`MAX_LUECKEN = 0`): was am Buch hängt und keine dieser Kategorien ist, reist mit.

## Code

- **`lib/book-bundle.js`** — pure Builder/Parser/Validator (kein Express/DB, Round-Trip testbar): `buildManifest`, `normalizeIncludes`, `treeToNodes`, `buildBookJson`, `validateManifest`, `validateBookJson`, `planFromNodes`. `planFromNodes` flacht den node-Tree in eine geordnete Op-Liste (`chapter`/`page` mit `tempId`/`parentTempId`/`srcId`); Tiefe > 3 wird gekappt (Pages hängen am letzten erlaubten Vorfahr, `cappedChapters` zählt das).
- **`db/book-migration-data.js`** — `collectExtras(bookId, { analysis, lektorat, chats, research }, scopeEmail)` (book-scoped SELECTs, JOIN-Scoping für Bridge-Tabellen, Analyse-Block auf einen `user_email`-Scope) + `restoreExtras(bookId, extras, { pageIdMap, chapterIdMap }, importerEmail)` (eine `db.transaction`, alle Inserts mit ID-Remap + `user_email`→Importer). Direkter SQL-Zugriff bewusst — Analyse-Entities fallen nicht unter die Content-Store-Facade (die gilt nur für Pages/Chapters/Books).
- **Export — `GET /book-migration/:bookId`** ([routes/book-migration.js](../routes/book-migration.js), sync, in `server.js` gemountet): Query-Flags `?analysis=1&lektorat=1&chats=1&research=1`. ACL `viewer` (reiner Content-Export) bzw. **`owner`**, sobald ein Extra angefordert wird (Extras enthalten potenziell personenbezogene Daten aller Mitarbeitenden). → `bookTree` + Page-HTML via Content-Store → `treeToNodes` (mit srcId) → `getBookSettings` → `collectExtras` → JSZip (book.json + optionale Extra-Dateien) → Stream `application/zip`. Leeres Buch → 400, fehlend → 404.
- **Import — `POST /jobs/book-import`** ([routes/jobs/book-import.js](../routes/jobs/book-import.js), Job-Queue, spiegelt das Buffer-Pattern von folder-import): raw ZIP (Limit 200 MB, sonst `413 ZIP_TOO_LARGE`) → `importBuffers` ([lib/import-buffers.js](../lib/import-buffers.js)#`ImportBufferStore`, TTL 30 min, ein offener Upload pro User, Summe über alle User gedeckelt; sonst `429 IMPORT_PENDING` bzw. `429 IMPORT_CAPACITY`) → Job `book-import` (bookId 0). Dedup-Key `swbook:<sha256>` (`contentHash` über den Upload): derselbe Upload zweimal ergibt denselben Job, zwei gleich grosse Dateien bleiben verschieden. Worker `runBookImportJob`: `openCappedZip` ([lib/zip-limits.js](../lib/zip-limits.js), Deckel `SWBOOK_ZIP_LIMITS`: Einträge, Bytes je Eintrag und gesamt — gezählt **während** des Entpackens, Überschreitung → `job.error.archiveTooLarge`) → `validateManifest`/`validateBookJson` → Buchname nach `bookNameError` (sonst `job.error.bookNameInvalid`) → `createOwnedBook` ([lib/book-create.js](../lib/book-create.js): Buch + Owner-Grant als Einheit, scheitert der Grant, wird das Buch wieder entfernt und der Job endet mit `job.error.bookCreateFailed`) → Buch-Settings → Ops in Reihenfolge via `materializeOps` (Content-Store-Facade), dabei `pageIdMap`/`chapterIdMap` aus `op.srcId` → neue ID füllen → `restoreExtras` (gemäss `manifest.includes`, **non-fatal**) → Vortags-Baseline-Snapshot (`lib/import-baseline.js#seedImportBaseline`) → `completeJob({ bookId, bookName, pagesCreated, chaptersCreated, cappedChapters, extras, failed, pagesInBundle })`. **Teilimport sichtbar:** einzeln gescheiterte Kapitel/Abschnitte (`failed`) und ein zurückgerollter Extra-Block (`extras.error`) zeigt die Import-Karte als Warnzeilen — ein Umzug, der nur halb ankam, darf nicht wie ein vollständiger aussehen. Hatte das Bundle Abschnitte und wurde **keiner** angelegt, endet der Job mit `job.error.swbookNoPagesCreated`. **Rückbau:** bei Abbruch (pro Op `throwIfCancelled` im `onProgress`) oder Fehler, bevor die Abschnitte stehen, wird das angelegte Buch zurückgenommen (`discardImportedBook`); danach nicht mehr.

Seiten-HTML läuft beim `createPage` durch den Sanitization-Chokepoint (`_cleanHtmlSafe`) → kein XSS-Import. Manifest-Validierung vor jeder Verarbeitung: falsches `format`/fehlend → `job.error.badManifest`, Version > 2 → `job.error.unsupportedVersion`, leeres `book.json`/leerer Tree → `job.error.swbookEmpty`. Schlägt nur die Extra-Wiederherstellung fehl, bleibt das Buch mit Inhalt bestehen (`extras: { error: true }` im Resultat).

## Frontend

- **Export-Card** ([public/js/book/export.js](../public/js/book/export.js) + [partials/export.html](../public/partials/export.html)): Migration-Button zieht `/book-migration/<bookId>` (gleicher Blob-Download wie reguläre Exporte). Nur scope=book. Drei `.form-check`-Checkboxen (`migrateAnalysis`/`migrateLektorat`/`migrateChats`) hängen die Query-Flags an. Nur Owner sieht beim Anhaken einen erfolgreichen Download (Server gated auf `owner`).
- **folder-import-Card** ([public/js/cards/folder-import-card.js](../public/js/cards/folder-import-card.js) + [partials/folder-import.html](../public/partials/folder-import.html)): zweiter Modus „Schreibwerkstatt-Buch (.swbook)" — File-Input → `POST /jobs/book-import` → Job-Polling → bei Done Navigation zum neuen `bookId`. Das Resultat zeigt die wiederhergestellten Extra-Zähler (analysis/lektorat/chats). Import übernimmt automatisch, was im Bundle steckt — keine Import-seitige Auswahl.
- **Dateiöffner der installierten App**: [manifest.webmanifest](../public/manifest.webmanifest) meldet `.swbook` als `file_handlers`-Typ. Öffnet das Betriebssystem eine solche Datei mit der App (nur Chromium, nur installiert), übergibt [app/boot/file-launch.js](../public/js/app/boot/file-launch.js) sie aus `window.launchQueue` an die Import-Karte (`EVT.IMPORT_FILE_LAUNCHED`, Rückfall `window.__pendingImportFile`, falls das Partial noch nicht geladen ist). Derselbe Verbraucher reicht Shortcut-Ziele als Hash durch — mit `launch_handler: focus-existing` navigiert der Browser ins schon offene Fenster nicht selbst.
