# Fassungen (Manuskript-Meilensteine)

Ganze-Buch-Schnappschüsse: der User friert den aktuellen Stand des **gesamten** Buchs per Knopfdruck als „Fassung 1/2/3…" ein, vergleicht zwei Fassungen miteinander, **öffnet** eine Fassung nur-lesend (Reader), **exportiert** sie (HTML/TXT/MD/EPUB/DOCX + Custom-PDF), **markiert** eine Fassung als veröffentlichte Auflage (Publikations-Anker + Lösch-Schutz) und kann das Buch auf eine Fassung **zurücksetzen** (Restore). Reader + Export operieren auf dem selbsttragenden `content_json` der Fassung — der aktuelle Buchstand bleibt dabei unberührt. Pro Buch skopiert, user-initiiert (+ eine Auto-Fassung beim Fertig-Markieren), kein Pruning (Gegenstück zu `page_revisions`, die seitenweise + automatisch entstehen). Route: `#book/:bookId/fassungen`.

## Datenmodell

Eine Zeile pro Fassung in `book_snapshots` ([db/book-snapshots.js](../db/book-snapshots.js), Schema in [db/migrations.js](../db/migrations.js) / [db/squashed-schema.js](../db/squashed-schema.js), ERD in [docs/erd.md](erd.md)):

- `id` (PK), `book_id` (FK → `books(book_id)` ON DELETE CASCADE)
- `seq` — fortlaufende Fassungsnummer pro Buch (1-basiert, **monoton**; Löschungen recyceln keine Nummer, damit „Fassung 3" stabil bleibt). `_nextSeq` = `MAX(seq)+1`.
- `label`, `description` — optionaler Name + Notiz (geclippt auf 120 / 1000 Zeichen).
- `content_json` (NOT NULL) — **selbsttragende** Momentaufnahme im `buildBookJson`-Format `{ book: { name, description, settings }, tree: [node…] }` mit Seiten-HTML **inline**. Spiegelt den swbook-Export ([routes/book-migration.js](../routes/book-migration.js)), nur als DB-Zeile statt ZIP. Bleibt gültig, auch wenn Seiten später gelöscht werden. Jeder Knoten trägt seine `srcId` (page_id bzw. chapter_id zum Capture-Zeitpunkt) — Diff, Drift und Restore matchen darüber. Kapitel-Knoten tragen zusätzlich `excluded` (Export-Ausschluss). Die Reihenfolge kommt aus dem `book_order`-Tree (`treeToNodes(…, orderTree)`) und hält damit auch das **Interleaving** (Seite zwischen zwei Kapiteln). `settings` umfasst alle authored Felder aus `SETTINGS_KEYS` ([lib/book-bundle.js](../lib/book-bundle.js)) inkl. Stilprofil, Zielvorgaben, Zitier-/Verzeichnis-, Querverweis-, Textsorten- und Recherche-Einstellungen — nie `allow_lektor_book_chat` (ACL).
- `extras_json` — `collectExtras(bookId, { analysis, lektorat })` (reiner DB-Read, kein KI-Call). Der Rohblob wird gespeichert, aber **nicht** an den Client geliefert und beim Restore **nicht** wiederhergestellt (bewusst — ein Voll-Restore der Analyse-/Lektorat-Tabellen ist nicht Teil der Inhalts-Fassung). `GET /snapshots/:bookId/:id` liefert daraus eine **kompakte Zähl-Übersicht** (`extras_summary` via `extrasSummary`: Figuren/Orte/Szenen/Ereignisse/Weltfakten/Kontinuitäts-Befunde/Ideen/Lektorats-Befunde, nur Blöcke >0) — der Reader zeigt sie als Publikations-Nachweis „so sah der Weltaufbau/das Lektorat zu diesem Zeitpunkt aus".
- `published_at` — `NULL` = nicht veröffentlicht; sonst ISO+Z-Zeitpunkt der Markierung als **veröffentlichte Auflage**. Publikations-Anker (welche Fassung erschienen ist, mit eingefrorener ISBN/Titelei aus `publication_json`) + **Lösch-Schutz** (Delete verlangt `?force=1` + Owner). Mehrere Fassungen dürfen gleichzeitig markiert sein (eine pro Auflage). Gesetzt via `POST /snapshots/:bookId/:id/publish` (`setPublished`), in `listSnapshots` + `GET single` ausgeliefert.
- `publication_json` — **eingefrorene, selbsttragende Kopie** von `book_publication` zum Capture-Zeitpunkt (freeze-only, nicht pro Fassung editierbar): `{ meta: {…getMeta-Textfelder inkl. epub_*…}, cover: {b64,mime}|null, authorImage: {b64,mime}|null }`. Nur gesetzt, wenn eine echte `book_publication`-Zeile existiert (`getMeta().created_at`), sonst `null` → Export fällt auf die Live-Defaults zurück. Cover/Autorfoto werden als base64 mitgeführt (Fassung ist damit auch bzgl. Titelei/Cover self-contained). Der Fassungs-Export (PDF/EPUB/Sync) nutzt diese Kopie via `snapshotPublication` ([lib/snapshot-export.js](../lib/snapshot-export.js)); Restore schreibt sie zurück. `listSnapshots` liefert `has_publication` als Flag (analog `has_extras`), der volle Blob wird nie in der Liste ausgeliefert.
- `chars` / `words` / `pages` / `chapters` — Kennzahlen, berechnet beim Erstellen aus dem inline-HTML (gleiche Normalisierung wie `page_stats` via `htmlToPlainText`). Kein retroaktives Update.
- `lektorat_metrics` — verdichtete Fehler-Kennzahl beim Capture: JSON `{ open, applied, all, words_checked }`, die drei Modi jeweils `{ total, byTyp: { typ: count } }`, berechnet aus den eingefrorenen `page_checks` via [lib/lektorat-metrics.js](../lib/lektorat-metrics.js) (dieselbe Zählregel wie die Live-Fehler-Heatmap, [lib/lektorat-findings.js](../lib/lektorat-findings.js), aber buchweit statt pro User). `words_checked` = Wörter der geprüften Seiten der Fassung. Basis für den **Fehlerdichte-Trend über die Fassungen** in der Fehler-Heatmap-Karte (`GET /history/fehler-trend/:book_id`; y = `total / words_checked × 1000`, bei älteren Fassungen ohne das Feld ersatzweise `/ words` als markierte Näherung — Regel in [lektorat.md](lektorat.md#auswertung-fehler-heatmap--fehlerdichte-trend)). Bestehende Fassungen wurden per Migration 239 aus `extras_json` backfilled; Fassungen ohne Lektorat-Daten bleiben `null`.
- `user_email`, `created_at` (ISO+Z).
- Index: `idx_book_snapshots_book (book_id, created_at DESC)`.

## Routen ([routes/snapshots.js](../routes/snapshots.js))

Alle book-scoped (`setContext({ book })`), ACL via `guardBook`. Synchroner Pfad (reiner DB-Read/-Write, kein KI-/Netz-Call) — bewusste Ausnahme zur Job-Queue-Regel, analog zum Capture.

- `GET /snapshots/:bookId` (viewer) — Meta-Liste **ohne** `content_json`/`extras_json` (können MB groß sein), `has_extras` als Flag, `size_bytes` (Speicherbedarf der drei JSON-Blobs; `octet_length` liest nur den Zellen-Header, nicht den Inhalt), DESC nach `created_at`.
- `GET /snapshots/:bookId/:id` (viewer) — Vollzeile inkl. geparstem `content` + `published_at` + `publication` (Text-Meta ohne Cover/Foto-BLOBs, für den Metadaten-Diff) + `extras_summary` (Zähl-Übersicht). Quelle für Diff, Reader **und** Publikations-Metadaten-Diff.
- `GET /snapshots/:bookId/drift` (viewer) — **„lohnt sich eine neue Fassung?"**: vergleicht den aktuellen Buchstand mit der **jüngsten** Fassung (`getLatestSnapshot`), ohne eine anzulegen. Baut den aktuellen Stand als **light**-Payload (`buildSnapshotPayload(…, { light: true })`: Text, Struktur, Settings, Publikations-Text-Meta — ohne Bild-BLOBs, Cover-base64 und Analyse-Extras) und rechnet über [lib/snapshot-drift.js](../lib/snapshot-drift.js) (pure, node:test-bar) vier Achsen: **Text** = Anteil des editierten Wort-Volumens (Wort-Diff je Seite via `diff`, Match über `srcId`; neue/entfernte Seiten zählen mit vollem Volumen; symmetrischer Nenner `base+cur` → 0% unverändert, ~100% Voll-Umschrieb), **Buch-Kopf** = Titel/Beschreibung, **Publikation** = geänderte `book_publication`-Felder (Spiegel der `PUB_*_FIELDS` aus [book-snapshot-diff.js](../public/js/book-snapshot-diff.js)), **Einstellungen** = geänderte `SETTINGS_FIELDS` — nur was Text oder Ausgabe betrifft; Arbeits-/Status-Felder (fertig, Tages-/Zielvorgaben, Statistik-Ausschluss, extrahiertes Stilprofil, Recherche-Profil) zählen nicht. `worthwhile` = Text-Drift ≥ `TEXT_THRESHOLD` (0.10) **oder** eine Feld-Achse geändert. Ohne Fassung → `{ hasBaseline: false }`. Muss **vor** `/:bookId/:id` gemountet sein (sonst schluckt `:id` das Literal `drift`).
- `GET /snapshots/:bookId/:id/export/:fmt` (viewer) — synchroner Fassungs-Export in `html`/`txt`/`md`/`epub`/`docx`. Baut das Export-Bundle via `snapshotToBundle` ([lib/snapshot-export.js](../lib/snapshot-export.js)) aus dem `content_json` (statt Live-Buch; Kapitel mit `excluded` fallen samt Unterkapiteln weg wie im Live-Export), rendert mit demselben `FORMATS[fmt].build` wie [routes/export.js](../routes/export.js) und teilt dessen Meta-/Antwort-Helper ([lib/export-send.js](../lib/export-send.js)). `pdf` ist hier bewusst **ausgeschlossen** (`BAD_FORMAT`) — PDF läuft über den Job (Profile). Filename-Slug `…-fassung-<seq>`. Fehler: `SNAPSHOT_NOT_FOUND` (404), `CORRUPT_SNAPSHOT` (422).
- `POST /snapshots/:bookId` (editor) — „Fassung speichern". Baut Payload via `buildSnapshotPayload` ([routes/snapshots/payload.js](../routes/snapshots/payload.js), geteilt mit Restore-Backup, Auto-Fassung und Drift) und legt eine Zeile an. `BOOK_EMPTY` → 400.
- `POST /snapshots/:bookId/:id/restore` (editor) — setzt das Buch auf die Ziel-Fassung zurück (siehe „Restore-Pipeline", Code [routes/snapshots/restore.js](../routes/snapshots/restore.js)).
- `POST /snapshots/:bookId/:id/restore-node` (editor) — Body `{ kind: 'page'|'chapter', srcId }`: übernimmt nur diese Seite bzw. dieses Kapitel (samt Inhalt) aus der Fassung, löscht nichts. Existiert die Seite noch, wird ihr Inhalt ersetzt (der vorige Stand bleibt im Seiten-Verlauf); fehlt sie, entsteht sie neu im ursprünglichen Kapitel, sonst auf Buch-Ebene. Antwort trägt `pageId`. Fehler: `NODE_NOT_FOUND` (404), `BAD_KIND` (400), `RESTORE_RUNNING` (409).
- `POST /snapshots/:bookId/:id/publish` (editor) — Body `{ published: bool }`, markiert die Fassung als veröffentlichte Auflage (`published_at` setzen/nullen).
- `DELETE /snapshots/:bookId/:id` (editor) — veröffentlichte Fassung (`published_at` gesetzt) ist geschützt: ohne `?force=1` → `409 SNAPSHOT_PUBLISHED` (Frontend zeigt eine stärkere Bestätigung, dann erneut mit `force`); mit `force` zusätzlich **Owner-Rolle** Pflicht (sonst `403`) — die Nachweis-Kopie einer erschienenen Auflage entfernt kein Mitautor im Vorbeigehen.

Zusätzlich exportiert das Modul `captureSnapshot(bookId, req, { label, description, dedup, userEmail })` — wiederverwendbarer, best-effort (wirft nie) Capture-Einstieg für Auto-Sicherungen aus anderen Routen. `dedup:true` überspringt, wenn die jüngste Fassung denselben Manuskript-Stand hält (Vergleich des node-Trees — Text, Struktur, Namen; Settings bleiben aussen vor, weil das Fertig-Markieren sie selbst ändert). Genutzt von [routes/booksettings.js](../routes/booksettings.js): beim Fertig-Markieren des Buchs (`is_finished` 0→1) wird fire-and-forget eine Fassung `__i18n:snapshots.autoFinishLabel__` festgehalten (Publikations-Meilenstein).

## Restore-Pipeline

`POST /snapshots/:bookId/:id/restore` setzt das Buch auf den Stand der Ziel-Fassung — **an Ort und Stelle** über [lib/bundle-apply.js](../lib/bundle-apply.js)#`materializeOps` (geteilt mit `restore-node` und dem `.swbook`-Import). Reihenfolge (Pflicht):

0. **Sperren** — editiert gerade ein **anderer** User am Buch (Live-`page_presence.listForBook`, stale-gefiltert >90 s; eigene Presence auch auf anderen Geräten zählt nicht), → `409 BOOK_BUSY` mit `editors:[names]`, **bevor** irgendetwas angefasst wird. Der Client (`restoreSnapshot`) zeigt eine stärkere `appConfirm` mit den aktiven Namen und wiederholt mit `?force=1`. Best-effort — schlägt der Presence-Read fehl, wird nicht geblockt. Läuft für das Buch schon ein Restore (auch `restore-node`, prozess-lokales Set), → `409 RESTORE_RUNNING`.
1. **Ziel planen** — `content_json` parsen → `validateBookJson` → `planFromNodes(tree)`. Defekt/leer → 422 `CORRUPT_SNAPSHOT`, bevor irgendetwas angefasst wird.
2. **Auto-Sicherung** — der aktuelle Stand wird als neue Fassung mit Label `__i18n:snapshots.autoBackupLabel__` abgelegt → **Restore ist umkehrbar**. `BOOK_EMPTY` ist ok; jeder andere Fehler → 500 `BACKUP_FAILED`, bevor etwas geschrieben wird.
3. **Kapitel zuordnen** — pro Kapitel-Op: existiert `srcId` noch als Kapitel dieses Buchs, wird **dieses** Kapitel aktualisiert (Name, `excluded`), sonst neu angelegt (`createChapter`). Kapitel laufen **vor** den Seiten, damit jeder Querverweis seine Ziel-ID kennt.
4. **Seiten zuordnen** — pro Seiten-Op: existiert `srcId` noch, wird **diese** Seite per `savePage` auf HTML + Name der Fassung gesetzt (nur bei Abweichung; Revision mit `source: 'import'`), sonst neu angelegt. Kapitel-Querverweise (`data-xref-id`) auf neu angelegte Kapitel werden auf die neue chapter_id umgeschrieben (`remapChapterXrefs`). Mitgeführte Bild-BLOBs werden nur eingefügt, wo die referenzierte `page_images`-Zeile der Seite fehlt.
5. **Überzähliges entfernen** — Seiten, die seit der Fassung hinzukamen, per `deletePage` (→ Papierkorb, wiederherstellbar), danach nicht mehr zugeordnete Kapitel. Seiten zuerst: `pages.chapter_id`/`chapters.parent_chapter_id` sind `ON DELETE SET NULL`.
6. **Reihenfolge** — `bookOrder.putOrder` mit dem aus den Ops gebauten Tree (`orderTreeFromOps`): Hierarchie + Interleaving exakt wie in der Fassung. Scheitert die Validierung, fällt der Restore auf `clearOrder` + `ensureTree` zurück und zählt das als Fehler.
7. **Settings** — `applyBundleSettings`: nur Keys, die die Fassung trägt, überschreiben; alles andere (ältere Fassung ohne spätere Felder) bleibt. `allow_lektor_book_chat` wird **nie** aus der Fassung gesetzt — der aktuelle Wert bleibt.
8. **Buch-Kopf** — Name + Beschreibung der Fassung (`updateBook`, nur bei Abweichung).
9. **Publikation** (best-effort, nur wenn `publication_json` gesetzt): `upsertMeta` + Cover/Autorfoto auf den eingefrorenen Stand — fehlt ein BLOB in der Fassung, wird das Live-Bild gelöscht. Umkehrbar über die Auto-Sicherung.
10. **Stats-Sync** (`syncBook`).

Antwort: `{ ok, seq, pagesCreated, chaptersCreated, pagesUpdated, chaptersUpdated, pagesDeleted, chaptersDeleted, failed }`. `failed > 0` meldet das Frontend als Teil-Erfolg (`snapshots.restoredPartial`).

**Invarianten / Konsequenzen:**
- **IDs bleiben stabil**, solange die Seite/das Kapitel noch existiert — und mit ihnen alles, was per FK daran hängt: Share-Links samt Leser-Kommentaren, Ideen, Blog-/HubSpot-Verknüpfungen (kein Doppel-Post beim nächsten Sync), Recherche-Links, Seiten-Verlauf, Szenen-/Ereignis-Anker. Reader-Diff, Vergleich und Drift matchen danach weiter über `srcId`.
- Nur **neu angelegte** Knoten bekommen neue IDs (die Seite/das Kapitel war seit der Fassung gelöscht worden) — deren FK-Daten waren mit dem Löschen bereits weg.
- Nicht-transaktional (wie der Buch-Import); Einzelfehler zählen in `failed` statt zu werfen. Die Auto-Sicherung ist die Absicherung gegen einen abgebrochenen Lauf.
- `extras_json` wird nicht zurückgeschrieben (Analyse/Lektorat sind nicht Teil der Inhalts-Fassung).

## Frontend

[public/js/cards/snapshots-card.js](../public/js/cards/snapshots-card.js) (`Alpine.data('snapshotsCard')`) + [public/partials/snapshots.html](../public/partials/snapshots.html). `showSnapshotsCard` bleibt im Root (Hash-Router + Exklusivität), fachlicher State in der Sub-Komponente. Registry-Eintrag in [feature-registry.js](../public/js/cards/feature-registry.js) (`key: 'snapshots'`, `minRole: 'editor'`, `requiresPages: true`).

- **Speichern** — Name + Notiz (optional, `data-spellcheck`) → `captureSnapshot`.
- **Drift-Hinweis** — unter der Capture-Leiste: `loadDrift` ruft nach `loadSnapshots` (nur bei ≥1 Fassung) `GET …/drift` und rendert einen Hinweis-Block (`.snapshots-drift`, `--worth`-Modifier = amber-getönt bei `worthwhile`) mit Kurz-Fazit (`driftHeadline`) + Detail-Tags (`driftItems`: Text-%, geänderte/neue/entfernte Seiten, Buchtitel/Publikation/Einstellungen geändert). Best-effort — bei Fehler bleibt der Hinweis aus. **Wegklickbar** (`dismissDrift`): das Wegklicken merkt sich eine kompakte Drift-**Signatur** (`_driftDismissKey`: Baseline-id + Text-% + Seiten-Zähler + Publikations-/Einstellungs-/Buchkopf-Flags) in `localStorage['sw:snapshotDrift:dismissed:<bookId>']`. `showDrift()` blendet den Block aus, solange die gespeicherte Signatur der aktuellen entspricht — sobald sich am Buch relativ zur jüngsten Fassung etwas Messbares tut (oder eine neue Fassung die Baseline wechselt), unterscheidet sich die Signatur und der Hinweis kommt wieder. Kein Server-State, pro Buch + Browser.
- **Liste** — `entity-grid-table` (Standard-Tabellenklasse, sortierbar via `sortableTable`, `persistKey: 'book.snapshots'`), inkl. Spalte **Grösse** (`size_bytes` via `fmtBytes`). Numerik-Spalten rechtsbündig über `.snapshots-table .snapshots-num` (schlägt die linksbündige `entity-grid-table`-Default-Regel per Specificity). Autor-Chip nur bei geteilten Büchern. Veröffentlichte Fassungen tragen einen „Veröffentlicht"-Badge (`isPublished` / `publishedDateLabel`) in der Fassungs-Zelle.
- **Veröffentlichen** — `togglePublish` (`POST …/publish`) markiert die Fassung als Auflage bzw. entfernt die Markierung; `publishingId` sperrt den Button. Der Publikations-Anker + `publication_json` machen die erschienene Auflage reproduzierbar.
- **Öffnen (Reader, read-only, Diff gegen aktuell)** — `openSnapshot` lädt parallel `GET /snapshots/:bookId/:id` (Fassungs-`content`) **und** `GET /book-editor/:bookId/contents` (aktueller Buchstand). Die Render-Sektionen baut `fromSnapshotTree(content.tree)` aus dem geteilten Stream-Modell [public/js/manuscript-stream.js](../public/js/manuscript-stream.js) (geteilt mit Bucheditor `fromPages` und Share-SSR `fromGroups`); der Reader ergänzt pro Page die Diff-State-Felder (`status`/`renderHtml`). `entry.id` = alte page_id (srcId), gegen die der Inline-Diff matcht. Rendert ein Vollbild-Overlay (Modal-Charakter, Esc/Backdrop schliessen, `closeReader`) im **Bucheditor-Look** — reuse der `.book-editor-*`-Stream-/Block-Klassen aus [book-editor.css](../public/css/editor/book/book-editor.css), rein lesend (kein `contenteditable`, kein Save). Pro Seite ein **Inline-Wort-Diff** gegen die aktuelle Version (Match Fassungs-`srcId` == aktuelle `page_id`): `renderInline(fassungHtml, aktuellHtml, diffLib)` aus [page-revision-diff.js](../public/js/page-revision-diff.js) (einspaltig, `del`=seither gelöscht, `ins`=seither hinzugefügt; gleiche Block-/Wort-Pipeline wie `renderSideBySide`, aber ohne Spalten/Collapse). Seiten ohne aktuelles Pendant → Badge „im aktuellen Buch gelöscht"; seit der Fassung neu hinzugekommene Seiten werden als Fussnote gezählt (`readerAddedSince`). Unveränderte Seiten rendern das rohe Fassungs-HTML. Der Reader-Header zeigt zusätzlich den „Veröffentlicht"-Badge sowie einen **Publikations-Nachweis-Strip** aus `extras_summary` (`readerExtraItems`): Zähl-Tags für den eingefrorenen Weltaufbau-/Lektorat-Stand. CSS: [snapshot-reader.css](../public/css/components/snapshot-reader.css).
- **Export** — im Reader-Header: Schnell-Formate (HTML/EPUB/DOCX/MD/TXT) als Download-`<a>` auf die Sync-Route; **PDF** über eine Profil-Combobox (`/pdf-export/profiles`) → `POST /jobs/pdf-export` mit `snapshot_id` → Polling via `startPoll` → Download `/jobs/pdf-export/:id/file`. Der PDF-Job ([routes/jobs/pdf-export.js](../routes/jobs/pdf-export.js)) baut bei gesetztem `snapshotId` das Bundle via `snapshotToBundle` statt `loadContents`; `scope`/`target` sind dann fix `book`/`interior`. Publikations-Metadaten (Cover/Titelei/epub_*) kommen aus der **eingefrorenen `publication_json`** der Fassung (via `snapshotPublication`), nicht aus dem Live-`book_publication` — ein Export von „Fassung 3" trägt also das Impressum/Cover von damals. Fehlt die eingefrorene Publikation (alte Fassung vor Migration 235, oder Buch ohne `book_publication`-Zeile), fällt der Job auf die Live-Daten zurück. Gilt gleichermaßen für den EPUB-Job und den synchronen Sync-Export ([lib/export-send.js](../lib/export-send.js)#`buildExportMeta` nimmt `{ publication }`). Das **Quellenverzeichnis** bauen Sync-Export und PDF-Job aus den Fundstellen im eingefrorenen HTML der Fassung (`citationsFromGroups`), nicht aus dem `source_citations`-Index des heutigen Seitenstands — sonst passten Chip-Nummern und Verzeichnis nicht zur Fassung; die Quellen-Stammdaten bleiben live. Dedup-Key trägt `:snap<id>`.
- **Wiederherstellen** ([snapshots-restore.js](../public/js/cards/snapshots-restore.js), in die Karte gespreadet) — `restoreSnapshot` mit `appConfirm(danger)`-Modal (kein natives `confirm()`); bei `409 BOOK_BUSY` (anderer User editiert gerade) eine zweite, stärkere `appConfirm` mit den aktiven Namen (`snapshots.busyConfirm`), dann erneut mit `?force=1`. Nach Erfolg `app.loadPages()` + Liste neu laden (Auto-Sicherung erscheint dort); `failed > 0` → Teil-Erfolgs-Meldung. `restoringId` sperrt die Zeile. **Im Reader** trägt jede geänderte/gelöschte Seite und jedes Kapitel einen Knopf „Seite/Kapitel übernehmen" (`restoreNode` → `restore-node`; Kapitel adressiert über `chapterId` = srcId aus `fromSnapshotTree`); danach lädt der Reader den Diff neu. `restoringNodeKey` sperrt die Knöpfe.
- **Löschen** — `deleteSnapshot` mit `appConfirm(danger)`-Modal; bei einer veröffentlichten Fassung antwortet der Server `409 SNAPSHOT_PUBLISHED` → stärkere `appConfirm` (`snapshots.deletePublishedConfirm`), dann erneut mit `?force=1`; ohne Owner-Rolle `403` → Hinweis `snapshots.deletePublishedOwnerOnly`.
- **Papierkorb (gelöschte Seiten)** — eigene Sektion am Kartenende ([snapshots-trash.html](../public/partials/snapshots-trash.html), Methoden [snapshots-trash.js](../public/js/cards/snapshots-trash.js)), nur sichtbar, wenn es etwas wiederherzustellen gibt. Siehe „Papierkorb" unten.
- **Vergleich** ([snapshots-compare.html](../public/partials/snapshots-compare.html), Methoden [snapshots-compare.js](../public/js/cards/snapshots-compare.js)) — zwei Comboboxen (Default: zweitneueste vs. neueste), Buch-Level-Diff via [book-snapshot-diff.js](../public/js/book-snapshot-diff.js) (`diffSnapshots`): Summen-Badges (hinzugefügt/entfernt/geändert/umbenannt/verschoben) + Zeichen-Delta, pro geänderter Seite lazy ein Wort-genauer Side-by-Side-Diff via [page-revision-diff.js](../public/js/page-revision-diff.js)#`renderSideBySide`. Zusätzlich ein **Publikations-Metadaten-Diff** (`diffPublication` derselben Datei) über die eingefrorenen `publication`-Text-Felder beider Fassungen (Autor/ISBN/Untertitel/Jahr/Verlag/Reihe/Widmung/Impressum/Copyright/Titelei-Text/Bio + Cover/Autorfoto vorhanden-ja/nein) — genau die publikationskritischen Felder, die der Inhalts-Diff nicht sieht. Als eigene Tabelle (`snapshots-pubdiff`), nur bei Änderungen sichtbar.
- `__i18n:`-Label-Marker (z.B. Auto-Sicherung) werden in `fassungLabel` via `_resolveLabel` in der Locale des Betrachters aufgelöst.

## Papierkorb (gelöschte Seiten)

Seiten werden hart gelöscht; `page_revisions` und `page_images` gehen per CASCADE mit. Damit eine versehentlich gelöschte Seite zurückkommt, sichert der Lösch-Chokepoint [localdb-delete.js](../lib/content-store/backends/localdb-delete.js)#`deletePage` **vor** dem `DELETE` Inhalt (`body_html`), Kapitel (`chapter_id`, FK SET NULL) und die im HTML referenzierten Bild-BLOBs (`images_json`, Format von `collectReferencedImages`) in die Zeile des Lösch-Logs `page_deletions`. Die Bilder müssen vorher gelesen werden — danach hat das CASCADE sie entfernt.

- **Routen** ([routes/content/trash.js](../routes/content/trash.js), minRole editor): `GET /content/books/:book_id/trash` listet wiederherstellbare Einträge (`body_html IS NOT NULL AND restored_at IS NULL`), `POST /content/books/:book_id/trash/:deletion_id/restore` → `contentStore.restoreDeletedPage`. Fehler: `404 TRASH_NOT_FOUND` (auch bei fremdem Buch), `409 ALREADY_RESTORED`.
- **Wiederherstellen** legt die Seite über `createPage` **neu** an (neue `page_id`), im alten Kapitel, falls es noch zu diesem Buch gehört, sonst auf Buch-Ebene; danach `restorePageImages` + Rewrite der Bild-Refs. `restored_at` wird **vorher** atomar gesetzt (Doppel-Klick/zwei Tabs) und bei Fehlschlag zurückgenommen. Die Zeile bleibt stehen — der Delta-Sync der nativen Clients ([clients.md](clients.md)) braucht die Löschung weiterhin.
- **Nicht wiederherstellbar**: Einträge vor Migration 299 (`body_html` NULL); der Versionsverlauf der gelöschten Seite. Seiten, die ein Fassungs-Restore entfernt (seit der Fassung hinzugekommen), landen regulär im Papierkorb. Gelöschte Bücher nehmen ihren Papierkorb mit (`page_deletions.book_id` CASCADE).
- Kein Ablauf: Einträge bleiben, bis sie wiederhergestellt werden.

CSS: [public/css/components/snapshots.css](../public/css/components/snapshots.css) (nur snapshot-spezifische Tweaks; Tabelle nutzt `entity-grid-table`, Diff-Zellen `revision-diff-*` aus `page/page-revision-viewer.css`). i18n-Keys: `snapshots.*` in [de.json](../public/js/i18n/de.json) / [en.json](../public/js/i18n/en.json).
